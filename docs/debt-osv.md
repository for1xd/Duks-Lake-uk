# Дебіторка: імпорт ОСВ (1С/BAS) і Debt Aging

Код: блок `OSV:BEGIN … OSV:END` в `index.html` та функція `dzCalc`.
У застосунку: Facility → Облік → Дебіторська заборгованість → **«З ОСВ»** (роль Dev).

## Розбір файлу (`osvParse`)
- Підтримуються xls і xlsx (SheetJS); береться перший аркуш, де знайдено дані.
- **Шапка:** рядок з групами «Сальдо на початок», «Оборот(и) за період», «Сальдо на кінець». Під ним — рядок «Дебет / Кредит». Колонки визначаються за цими підписами, а не за фіксованими позиціями.
- **Період:** з тексту шапки («за Жовтень 2026 р.» або «01.10.2026 – 31.10.2026»). Якщо він не збігається з відкритим місяцем, вікно попереджає.
- **Рядки:**
  - рядки рахунку (`361`), «Контрагенти», «Договори» та «Разом/Підсумок» пропускаються;
  - рядок-договір (`№4 від 01.03.2026`, «Договір…», «б/н») прикріплюється до попереднього контрагента;
  - решта — контрагенти, суми беруться з їхнього підсумкового рядка.
- **Значення:**

  | Поле | Звідки |
  |---|---|
  | `start` (старий борг) | Сальдо на початок: Дебет − Кредит. Передоплата зменшує борг |
  | `charge` (нарахування) | Обороти за період, Дебет |
  | `paid` (оплата) | Обороти за період, Кредит |
  | `osvEnd` (поточна дебіторка) | Сальдо на кінець: Дебет − Кредит |

  Якщо «поч. + нарах. − опл. ≠ кін.», рядок позначається попередженням.

## Зіставлення з резидентами
- **Порядок пошуку:**
  1. ручний вибір у вікні імпорту;
  2. таблиця аліасів `resolve/osv`;
  3. нечіткий пошук.
- **Нечіткий пошук:** ігнорує ТОВ/ФОП/АТ та лапки, транслітерує кирилицю й латиницю, рахує схожість Jaro-Winkler по значущих словах і перевіряє частини назви в дужках.
- **Пороги:**
  - ≥ 86% і без конкурента в межах 5% → зіставлено автоматично;
  - 72–86% або два схожих кандидати (наприклад, два «Волков» у різних будинках) → «Перевірити»;
  - нижче 72% → «Не знайдено»: можна обрати вручну, додати новим рядком або пропустити.
- Ручні рішення зберігаються в аліасах, тож наступного місяця ця назва зіставиться сама.
- Кілька контрагентів, прив'язаних до одного рядка, підсумовуються.

## Дедлайн (`osvDue`)
| Ситуація | Дедлайн |
|---|---|
| Кінцеве сальдо ≤ 0 | немає, статус «Сплачено» |
| Менеджер змінював дату вручну (`dueManual`) | лишається ручна дата |
| Є старий борг (сальдо на початок > 0) | не відсувається: лишається поточна дата, якщо вона не пізніша за 10-те число місяця, інакше — 10-те число попереднього місяця |
| Інакше | 10-те число звітного місяця |

## Категорії (`dzCalc`, рахуються на льоту від сьогоднішньої дати)
| Умова | Категорія |
|---|---|
| Борг ≤ 0 | без категорії, дата не показується |
| Старий борг не покритий оплатою (`start > 0` і `paid < start`) | Критичний / суд |
| До дедлайну | без категорії (поточна заборгованість) |
| Прострочка 0–5 днів | Технічний борг |
| 6–15 днів | Обдзвін менеджера |
| 16–30 днів | Претензія юриста |
| Понад 30 днів | Критичний / суд |
