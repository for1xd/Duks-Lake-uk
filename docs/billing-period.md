# Період споживання (вода, сміття)

Показники води й обсяги сміття знімають / вносять 1–5 числа за **попередній** місяць. Тому кожен запис має два поняття:

- **період споживання** — місяць, за який дані (`YYYY-MM`). Це місяць документа в базі: `wPeriods/2026-10`, `waste/2026-10`. Усі суми, графіки, баланс з Водоканалом, Excel і звіт інвестору рахуються по ньому.
- **дата зняття / внесення** — фактична дата (`YYYY-MM-DD`), окреме поле запису:
  - вода: `wPeriods/<період>.reads.<лічильник>.d` (ставиться разом із кінцевим показником — вручну, з фото, з Excel, з «Обходу будівель»);
  - сміття: `waste/<період>.rows.<рядок>.d` (ставиться разом з обсягом). Для старих рядків без `d` датою вважається `at` — час збереження обсягу.

## Правило N-го числа
Уся логіка — функції `bp*` / `billingPeriod` в `index.html` (розділ «Облік води», одразу після `perShift`):
- `billingPeriod(date, mod)` — дата 1..N-го → попередній місяць, після N → поточний;
- `bpN(mod)` — N з `settings/main.billDay = {all:10, water?, waste?}` (порожнє для модуля = як для всіх). Змінюють керівники УК і Dev: кнопка «до N-го» під перемикачем місяця.

Де використовується:
- перемикач місяця (`bpBar`): за замовчуванням відкриває `billingPeriod(сьогодні)`; підпис «споживання · показники знято 01–05.11.2026» / «вивезення · дані внесено …» / «дані ще не внесено»; під ним дата зняття (лише в минуле) і підказка «Дані від 03.11 → період: жовтень 2026»;
- імпорт Excel (вода, сміття): у перегляді файлу — період споживання й дата для всього файлу;
- «Обхід будівель» → показник води йде в `billingPeriod(дата обходу)`;
- плитка «Облік» і звіт інвестору (підпис «дані за жовтень 2026 · показники на 01–05.11»; «Головне за місяць» бере воду/сміття лише за місяць звіту);
- Excel: «Період: жовтень 2026» у заголовку і рядок «Показники знято: …» / «Дані внесено: …».

## Старі дані
Нічого не переноситься саме. Dev → «Перерахувати періоди за правилом N-го числа» (функції `bpm*` біля `devExport`): вибір модуля, перегляд «було → стане» з кількістю, резервна копія JSON перед записом, рядок у журналі. Не переносяться й показуються як «потребує уточнення»: записи без дати та ті, де в цільовому місяці вже є дані.

Не зачеплено: паркінг, дебіторка, екстрені ситуації, планове ТО, клінінг (дата події = період). «Електроенергія» поки лише заглушка без даних — коли з’явиться, використовувати `billingPeriod(d,'power')`.
