# Duck's Lake

Застосунок для команди (графіки змін, задачі, ролі, чат, облік, Facility). Один файл `index.html`, опублікований як Claude-артефакт з вбудованою базою; `src/` — згенеровані копії для індексації (`python3 tools/split_src.py` після правок). Документація модулів — у `docs/`.

## Дизайн-система Graphite Glass (тест)
- Код: CSS-блок «Graphite Glass (тест для Dev)» у кінці останнього `<style>` в `index.html`, правила з префіксом `html.gg`; опис у `docs/graphite-glass.md`.
- Тільки токени (`--gg-*` та перевизначені `--bg`, `--surface`, `--fg`, `--accent`…). Хардкод кольорів, тіней і радіусів у правилах компонентів заборонено.
- Теми дзеркальні: однакові компоненти й ефекти, різні лише значення токенів.
- Кожен компонент: обидві теми, стани hover / active / focus-visible / disabled, ширина 375 px без горизонтального скролу.
- Бізнес-логіку в задачах редизайну не змінювати.

## Перевірка агентами (обов'язково)
- Після будь-якої зміни UI запускати `design-critic`, `a11y-auditor`, `design-system-guardian` і показувати їхні звіти користувачу в чаті.
- Задача не завершена, поки `design-critic` < 8/10 або є блокери a11y / дизайн-системи. Максимум 3 цикли на сторінку, далі — зупинитись і пояснити.
- Перед комітом — `bug-hunter` зі звітом у чаті.
- У проєкті немає збірки, Playwright, axe чи Lighthouse: скріншоти робити вбудованим браузером з тестових сторінок (CSS застосунку + типова розмітка) або брати скріншоти від власника.
